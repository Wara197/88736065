# Peer Review: ทบทวนคุณภาพของโค้ด Student API

# 67160197 วราวุฒิ จำนงค์ผล

## 1. โค้ดใน index.js มีการตรวจสอบข้อมูลนำเข้า (validation) ก่อนประมวลผลหรือไม่

- มีการนำเข้า validation แต่ไม่ได้อยู่ใน index.js แล้วทำให้การ validation นั้นจะอยู่ที่ routes/students.js เช็คว่ามี name/major ครบไหม, name ยาวพอไหม, ชื่อซ้ำไหม, หา id เจอไหมก่อนแก้ไข/ลบ — จุดที่ยังขาดคือยังไม่เช็ค type ของข้อมูล เช่นถ้าส่ง name เป็นตัวเลขมาก็จะไม่ error

## 2. ทุก route มีการตอบกลับด้วย Status Code ที่เหมาะสมกับผลลัพธ์หรือไม่

- โดยรวมเหมาะสมมีความใช้ได้โดยระบุ 200 (สำเร็จ), 201 (สร้างสำเร็จ), 400 (ข้อมูลไม่ครบ/ไม่ถูกต้อง), 404 (หาไม่เจอ), 409 (ข้อมูลซ้ำ) ซึ่งตรงตามหลัก REST API ที่ควรใช้ ยังขาดแค่การรองรับ 500 สำหรับกรณี error ที่ไม่คาดคิดเช่น เซิร์ฟเวอร์มีปัญหาเอง

## 3. โครงสร้างโค้ดในไฟล์เดียวยังอ่านง่ายอยู่หรือไม่ หากมี route เพิ่มขึ้นอีก 10 เส้นทาง จะเกิดปัญหาใดตามมา

- หลังจากแยกเป็น Router จะอ่านง่ายขึ้นมากแต่ถ้าเพิ่ม route อีก 10 เส้นในไฟล์เดิมต่อไปเรื่อย ๆ จะเริ่มมีปัญหาที่เพิ่มขึ้นตามมา
- 1. ไฟล์ยาวและอ่านยากขึ้น
- 2. validation ซ้ำกันหลาย route
- 3. ทดสอบยาก เพราะ logic ปนอยู่กับ route handler
- 4. ถ้าทำงานเป็นทีม จะ merge conflict บ่อยขึ้นเพราะทุกคนต้องมารอแก้ไฟล์เดียวกัน
